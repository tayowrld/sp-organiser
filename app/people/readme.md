Пользователи и права доступа:
- Любой действующий пользователь может иметь персонал (`manager_id` у подчинённых), получать задачи и назначать задачи своим прямым подчинённым.
- `is_admin` открывает дополнительный раздел: создание и редактирование обычных пользователей своей команды.
- `is_superadmin` позволяет управлять всеми пользователями, переназначать руководителей и выдавать `is_admin`.
- Главный администратор защищён от изменения через форму. Назначить ещё одного главного администратора через интерфейс нельзя.
- Пользователя отключают через `is_active`, сохраняя задачи. Перед отключением руководителя его действующий персонал необходимо переназначить.
Входные параметры: пользователь, идентификатор сотрудника или руководителя.
Выходные параметры: безопасные данные пользователя или результат проверки доступа.
`canAssignTask` проверяет принадлежность сотрудника на сервере. `validManager` не допускает самоподчинения и циклов любого уровня. Права не зависят от устаревшего поля `role`.

Отделы:
- `department_id` хранит прямое назначение отдела только у администратора.
- `getDepartment(person)` возвращает отдел ближайшего администратора с назначением, проходя по цепочке `manager_id`. Если назначения нет — `null`.
- Персонал не хранит копии отдела: смена руководителя или назначения сразу меняет отображаемый отдел у всей подчинённой цепочки.
- Вложенный администратор с собственным назначением начинает новую ветку отдела; без назначения наследует отдел вышестоящего руководителя. При снятии флажка администратора прямое назначение очищается.
