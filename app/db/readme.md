Модуль работы с базой данных SQLite.

Входные параметры: путь к файлу [`data/app.sqlite`](../../data/app.sqlite)
Выходные параметры:
- инициализированное подключение `better-sqlite3`

Сценарии использования:
```ts
import db from './db'
const rows = db.prepare('SELECT * FROM users').all()
```

При открытии существующей базы автоматически добавляются флажки `is_admin`, `is_superadmin`, `is_active`, без повышения прав старых пользователей. `manager_id` задаёт руководителя независимо от административных прав. Старое поле `role` сохранено для совместимости данных и больше не определяет права.

Отделы хранятся в таблице `departments` (`id`, `name`). Миграция добавляет необязательный `users.department_id`; существующие пользователи остаются без прямого назначения, данные сохраняются.

Рабочая схема расширяется идемпотентно: состояния и версии задач, подтверждения, отдел назначения, смены, ежедневные шаблоны, передачи, ознакомления, уведомления, push-подписки и журнал действий. Включены WAL, внешние ключи и ожидание блокировки 5 секунд. `DATA_DIR` задаёт каталог данных, по умолчанию используется `./data`, в production — `/data`. Фотографии хранятся BLOB в событиях и входят в резервные копии SQLite.

На пустой базе создаётся только схема. Демонстрационные сотрудники, задачи и объявления отсутствуют. Первого администратора создаёт [`scripts/create-admin.mjs`](../../scripts/create-admin.mjs); существующие данные автоматически не очищаются. В Docker каталог `/data` сохраняется в постоянном томе.
