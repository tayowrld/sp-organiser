Модуль работы с базой данных SQLite.

Входные параметры: путь к файлу [`data/app.sqlite`](../../data/app.sqlite)
Выходные параметры:
- инициализированное подключение `better-sqlite3`

Сценарии использования:
```ts
import db from './db'
const rows = db.prepare('SELECT * FROM users').all()
```

При открытии существующей базы автоматически добавляются флажки `is_admin`, `is_superadmin`, `is_active`, без повышения прав старых пользователей. `manager_id` задаёт руководителя независимо от административных прав. Старое поле `role` сохранено для совместимости данных и больше не определяет права.

Отделы хранятся в таблице `departments` (`id`, `name`). Миграция добавляет необязательный `users.department_id`; существующие пользователи остаются без прямого назначения, данные сохраняются.

Рабочая схема расширяется идемпотентно: состояния и версии задач, подтверждения, отдел назначения, смены, ежедневные шаблоны, передачи, ознакомления, уведомления, push-подписки и журнал действий. Включены WAL, внешние ключи и ожидание блокировки 5 секунд. `DATA_DIR` задаёт каталог данных, в разработке и production используется `./data` в корне проекта. Фотографии хранятся BLOB в событиях и входят в резервные копии SQLite.

На пустой базе создаётся только схема. Демонстрационные сотрудники, задачи и объявления отсутствуют. Первого администратора создаёт [`scripts/create-admin.mjs`](../../scripts/create-admin.mjs); существующие данные автоматически не очищаются. В Docker каталог `data/` из корня проекта напрямую монтируется в `/app/data`.

Дополнительные поля задач мигрируются автоматически: `initiative` (личная инициатива), `deleted` (мягкое удаление), `deletion_requested` (запрос удаления), `client_id` (UUID создания для зависимых офлайн-операций). Старые задачи остаются поручениями. Мягкое удаление сохраняет историю и фотографии, но исключает задачу из рабочих списков и напоминаний. `notification_settings` хранит личные параметры начала и повторения напоминаний. Число пользователей с `is_superadmin = 1` не ограничено.

Настройки напоминаний перенесены в каждую задачу: `reminder_hours` — число часов до срока; `null` означает 12:00 Москвы предыдущего календарного дня. Повтор — каждые 4 часа до завершения или удаления. Личные настройки уведомлений больше не используются. Поле «Уведомить заранее» доступно при создании и редактировании задач и инициатив, включая офлайн-очередь. Старые задачи автоматически получают вариант «накануне в 12:00».
